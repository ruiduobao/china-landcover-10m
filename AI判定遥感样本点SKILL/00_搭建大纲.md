## 一、这个 Skill 要解决什么问题

遥感产品生产与论文里，**样本点的"标签是不是真的"**永远是最大的不确定性来源。典型任务有三类：

| 任务 | 示例 | 判读问题 |
|---|---|---|
| 标签核验 | FCS10 灌丛层 600 点真灌丛率 | 该点是不是灌丛？（是/否/无法判读） |
| 细类判别 | 东北 2023 训练池里标了"玉米/水稻/大豆" | 到底是不是玉米？还是大豆/水稻/其它？ |
| 成品精度 | M3-A 3210 通用点 | 这个 10 m 像元实际是什么地类？ |

共同需求：**批量、可复现、有据可查、能区分到详细地类（玉米、水稻、大豆、小麦、棉花、茶园、大棚……）**，而不是只到"耕地/林地/草地"。

## 二、为什么现有做法不够（本项目的教训）

1. **只看单一 10 m 哨兵影像，作物细类分不开**——玉米/大豆在 7 月单景上几乎同款；必须靠**物候（多时相）+ 田间结构（高分纹理）+ 管理特征（淹水/地膜/垄行）**三路证据。
2. **只看高分底图，会被"哪一年"骗**——Esri/Google 瓦片是多年拼接，冬天/旱季的玉米地看起来就是裸地；高分只解决"结构"，物候必须靠有日期的时序影像。
3. **AI 判读会有系统性偏置**——本项目实测：单遍 AI 在"低置信是"上判是率 100%，人工/二审只认 12%；干旱区 AI 把稀疏灌丛判成裸地。所以要有一套**防自证、防锚定**的协议：盲判批次（不给标签）、双遍复判、随机"否"审计、分歧优先复核。
4. **云端模型看不见本地数据**——所有给 AI 的提示必须把坐标、日期、指标数字**写进文本/图上**；凡是要 AI 判断的，都必须在图里画出来（十字丝、目标框、比例尺）。
5. **直接上"某产品说它是玉米"会锚定**——先盲判，再对照先验标签算一致率，不能反过来。

## 三、方法骨架（本 Skill 的核心流程）

```
输入点位(CSV/SHP: id, lon, lat, 可选先验标签/分层)
   │
   ├─ M1 输入质检：坐标系统一、去重、分层标注、生成判读编号
   │
   ├─ M2 高分影像：Esri World Imagery z18-19（主）→ Google 卫星（备）
   │        3×3 瓦片拼图 → 以点为中心裁 512px → 十字丝 + 目标框 + 编号
   │
   ├─ M3 时序影像：Sentinel-2 L2A 生长季多时相（云掩膜中位合成）
   │        真彩 / 假彩(NIR) / NDVI 时序曲线；水稻还要看淹水期
   │
   ├─ M4 辅助指标：冠层高度(GEDI/ETH)、树覆盖(Hansen)、DEM、先验产品交叉表
   │
   ├─ M5 判读执行：盲判联系表（只给编号）→ 逐点 [类别 + 置信 + 证据]
   │        细类判别走"作物决策树"（reference 里给判据）
   │
   ├─ M6 质控协议：双遍复判(≥90%) / 随机否审计(≥90%) / 分歧与低置信优先复核
   │
   └─ M7 汇总交付：合并表 + 一致率/精度报告 + SHP(WGS84+GCJ02) + 证据留档
```

**判读结论三态**：`是（确认先验标签）` / `否（给出实际类别）` / `无法判读（说明原因）`；
**每条结论必须带**：置信（高/中/低）+ 证据（影像特征 + 日期 + 辅助指标数值）。

## 四、功能模块清单（与脚本对应）

| 模块 | 职责 | 脚本 |
|---|---|---|
| M1 输入质检 | 点位表规范化、坐标系检查、分层/编号、判读表单骨架 | `prep_points.py` |
| M2 高分切片 | 多源瓦片抓取、拼图、标注渲染、断点续抓 | `fetch_chips.py` |
| M3 批阅组织 | 联系表（2×2/3×3）、盲判批次清单、批次不泄露标签 | `build_sheets.py` |
| M4 时序影像 | S2 生长季多时相合成（可选 STAC 免密钥 / GEE） | `s2_timeseries.py` |
| M5 辅助指标 | 冠层高度/树覆盖/物候振幅 汇总到表单 | `s2_timeseries.py --indices` |
| M6 质控协议 | 复判抽取、审计抽取、分歧归集、最小复核清单 | `qc_protocol.py` |
| M7 汇总交付 | 合并、一致率、精度报告、SHP 导出 | `merge_stats.py` / `points_to_shp.py` |
| 判读知识 | 详细地类判据（作物决策树、区域农时、影像源手册） | `references/*.md` |

## 五、Skill 的边界（不做什么）

- **不做**地类自动分类建模（那是生产链路的事），只做**点位级的判读与核验**；
- **不替代**双人人工盲判的法定效力：AI 判读严格标注为"预判读 / 二审"，正式裁决要么人工签字，要么明确写"AI 判读，未人工复核"；
- **不猜**：影像不可判就读不出来，宁记"无法判读"并给原因（云/阴影/影像太旧/目标<最小可判尺寸），不做"大概率是"的臆断；
- **不产出**没有证据链的数字——报告里的每个率都要能追到逐点表单。

## 六、验收标准（这个 Skill 算合格的条件）

1. **可跑通**：新用户只给一个 `points.csv`（id/lon/lat），三条命令内拿到切片+联系表；
2. **可区分细类**：玉米/水稻/大豆/小麦/棉花/茶园/大棚/果园 至少 8 类有明确判据，且判据是"影像上看得见的东西"，不是概念定义；
3. **可复现**：抽查任意点，能给出当时用的影像源、缩放级别、日期/季节、辅助指标数值；
4. **可质控**：内置双遍复判 + 随机否审计 + 分歧清单，能给出自一致率与审计准确率；
5. **可交付**：输出合并标签表 + 统计报告 + GIS 可直接打开的 SHP（含 WGS84 与 GCJ-02 双版）；
6. **诚实**：无法判读单独成列，不混入"否"，报告区分"实测值"与"正确解读"。
