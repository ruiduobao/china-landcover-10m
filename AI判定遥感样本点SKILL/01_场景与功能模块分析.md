# 01 场景分析与功能模块设计

> 上游：`00_搭建大纲.md` ｜ 方法来源：本项目 M3-B 二审（210 点）+ D0 材料链 + 五省生产踩坑记录
> 本文回答两个问题：**（A）真实使用中会遇到什么场景、怎么解；（B）Skill 因此必须具备哪些功能模块。**

## A. 场景与对策（按"用户会怎么卡住"组织）

### A1 影像源类

| 场景 | 现象 | 对策（已实测） |
|---|---|---|
| Esri 瓦片单块取不到 | 某块 404/超时/空白 | 单块重试 2 次 → 换 Google 卫星；**逐点记录实际源**（本项目 210 点中 191 纯 Esri、16 混用 Google） |
| Google 直连慢/被限 | 5 s+/瓦片，偶发重置 | 把 Google 降为**备源**；限制并发 ≤8–10/机（实测 24 并发劣化到 80–140 s/片） |
| 目标区云多/影像旧 | 真彩全糊或被云盖 | ①换 Google 比日期；②回退 **S2 生长季中位合成**（10 m）；③仍不行记"无法判读+原因" |
| 冬季/旱季底图把耕地拍成裸地 | 判"裸地"，其实是玉米茬 | **判作物必须看有日期的时序**，高分只判结构与边界；作物类结论以生长季影像为准 |
| 高纬/高海拔雪盖 | 真彩白茫茫 | 用夏季影像；或借 HANSEN/NDVI 判植被存在 |
| 目标 < 影像分辨率 | 大棚/垄行看不清 | 抬 z19（若该区有 0.3 m 数据）；仍看不清 → 降级为"小地物，记结构描述" |
| 瓦片带偏移（国内底图） | 与省界/矢量错位 300–700 m | 高分影像本身是 WGS84 像元坐标；**与国内 GCJ-02 矢量叠加要出 GCJ-02 版点位** |

### A2 判读执行类

| 场景 | 现象 | 对策 |
|---|---|---|
| AI/判读员被先验标签锚定 | 判读率虚高 | **盲判**：批次表只给 `point_id`，不出现先验类/分层/臂别 |
| 单张 512 图看得太累/漏点 | 210 张连读质量下降 | **联系表**：2×2 拼 512 原生（≤1568 px 不触发缩水）；3×3 会降采样，细节场景不划算 |
| 中心像元被十字线挡 | 看不见靶心 | 十字丝**中心留空**（≥48 px）；目标框按纬度算 10 m 边长（z18 约 20 px） |
| 判读结论不可复核 | 只写"是/否" | 强制三件套：**置信 + 证据 + 日期/源**；"否"必须填实际地类 |
| 判不出又不想留空 | 猜 | 允许并统计"无法判读"，报告里单列；不混入分母 |
| 边界点/混合像元 | 一半田一半路 | 记"中心像元主导地物"，并在证据里说明边界情况 |
| 细类分不开（玉米/大豆） | 单期同款 | 走**作物决策树 + 农时表**（见 `references/地类判读图谱.md`）：播种/淹水/抽穗/收获的时间窗 + 垄行几何 + 地膜/水田特征 |
| 同域多点判读疲劳 | 前后不一致 | 复判抽样：≥10% 点位重判，自一致率 <90% 时扩大复判并复核分歧点 |

### A3 质控与交付类

| 场景 | 现象 | 对策 |
|---|---|---|
| 审稿人问"判读可信吗" | 只有一个比率 | 出四件套：自一致率、随机"否"审计准确率、敏感性（推翻结论需要多大错判率）、无法判读占比 |
| 用户只要 GIS 看 | 拿到 CSV 不会用 | 导 SHP（**ASCII 字段名 ≤10 字符**，UTF-8 + .cpg），WGS84 与 GCJ-02 双版，附字段对照 |
| 结果要并回生产/训练池 | 键对不上 | 合并全部以 `point_id` 为键；输出保留原始列 + 判读列，不覆盖原表 |
| 判读标准漂移 | 不同批次宽严不一 | **预注册判据**（阈值先写死再跑）+ 判读规则书面化（是/否的操作定义） |
| 数据保密/代理 | 内网、需要代理 | 脚本支持 `--proxy`（socks5h://），不写入任何密钥；瓦片源可按需替换模板 |

## B. 功能模块设计（含接口）

### M1 `prep_points.py` — 输入质检与表单骨架
- 入：`points.csv`（必：`point_id, lon, lat`；可：先验类、分层、来源、备注）
- 做：坐标范围校验（中国 73–136°E/18–54°N 提示）、重复 id/重复坐标检测、WGS84 声明检查、生成判读表单骨架（空白 `结论/实际类别/置信/证据` 列）
- 出：`points_clean.csv` + `form_skeleton.csv` + 质检摘要
- 关键：**不让判读列出现在盲判批次里**

### M2 `fetch_chips.py` — 高分切片（核心）
- 入：`points_clean.csv`；参数：`--zoom 18|19`、`--crop 512`、`--source esri|google|auto`、`--proxy`、`--workers`
- 做：经纬度→Web Mercator 瓦片坐标；3×3 拼图；按点裁窗；叠加**十字丝（中心留空）+ 目标框（n 米，按纬度换算）+ 比例尺 + 编号**；断点续抓（切片已存在跳过）；逐点记录源与失败原因
- 出：`chips/<id>.png` + `fetch_log.json`
- 不变量：**点必须落在中心瓦片内**（否则裁窗越界）；裁剪偏移必须保证 512 窗口完整落在 768 拼图内

### M3 `build_sheets.py` — 批阅组织
- 入：`chips/`
- 做：按 2×2（默认）/3×3 拼联系表；**只写 point_id**；生成判读批次清单（每批 N 点）
- 出：`sheets/sheet_XX.png` + `sheet_map.json`
- 关键：单边 ≤1568 px，避免云端视觉模型缩放丢细节

### M4 `s2_timeseries.py` — 时序影像与辅助指标（可选、无密钥优先）
- 入：点位 + 年份 + 生长季窗口
- 做：Sentinel-2 L2A 多时相取窗（STAC 免密钥；GEE 为可选加强），云掩膜后中位合成真彩/假彩；算 NDVI/NDWI 时序与振幅；水稻点加看淹水期
- 出：`s2/<id>_季节.png` + 指标列（ndvi_amp/ndvi_peak/淹水证据/影像日期）
- 用途：**细类判别的物候证据**（高分只给结构）

### M5 `qc_protocol.py` — 质控协议
- 做：①复判抽样（随机 ≥10% + 全部低置信 + 全部"无法判读"）；②随机"否"审计（各层各抽 N）；③分歧归集（复判不一致、审计翻转、先验冲突）→ 生成最小复核清单
- 出：`qc/复判批次.csv`、`qc/审计批次.csv`、`qc/最小复核清单.csv`
- 判据（默认，可预注册覆盖）：自一致率 ≥0.90；"否"审计准确率 ≥0.90；否则扩大复核

### M6 `merge_stats.py` — 合并与统计
- 入：原始表 + 判读表单（可多批/多次）
- 做：按 `point_id` 合并；算确认率/一致率/混淆（先验×判读）；分组统计（按分层/区域/先验类）；敏感性（推翻结论所需错判率）；出报告 md
- 出：`merged_labels.csv` + `报告.md`

### M7 `points_to_shp.py` — GIS 交付
- 做：CSV→SHP；字段名 ASCII ≤10 + `字段对照.txt`；UTF-8 + `.cpg`；WGS84 与 GCJ-02 双版（GCJ-02 版注明元数据名义 EPSG:4326）
- 出：`shp/*.shp` 等 5 件套 ×2

### 参考文档（按需读，不进正文）
- `references/地类判读图谱.md`：**详细地类判据**（作物决策树：水稻/玉米/大豆/小麦/棉花/油菜/甘蔗/果园/茶园/大棚/蔬菜；林草水建的分型特征；每条判据写"在影像上看到什么"）
- `references/影像源与瓦片手册.md`：瓦片数学、源选择与备源、并发与代理、常见坑（黑块、旧影像、混合源）

## D. 设计红线（写进 SKILL.md 的硬约束）

1. 盲判批次**不得**含先验标签、臂别、分层字段；
2. 每条判读必须有**证据列 + 置信列**，缺一不算完成；
3. "无法判读"**单列**，不并入"否"；
4. 判读结论**必须可追溯到影像源与日期**；
5. 涉及正式结论（论文/交付）时，必须出**质控三率**（自一致率/审计准确率/敏感性），并声明"AI 判读是否经人工复核"；
6. 凭证/密钥**不进仓库**；瓦片抓取遵守源站条款，限速并发。
