# 02 三轮用户模拟迭代记录

> 目的：以"新用户拿着自己的数据来用这个 Skill"的方式，真跑真判，暴露缺口并当场修。
> 测试数据一律取自本项目真实资产（东北 2023 训练池的玉米/水稻/大豆补样点、HLJ），不是造的数据。
> 工作副本：`_试跑/轮1_东北作物/`（points.csv / chips / sheets / s2 / qc / shp / report.md）

## 轮 1｜"我有一批东北作物样本点，帮我核一下对不对"

### 用户输入与动作
```
points.csv：24 点（玉米 8 / 水稻 8 / 大豆 8，取自生产训练池 src=ne_crops_*_2023_HLJ）
python scripts/prep_points.py   --points points.csv --outdir . --prior-col 先验类 --strata-col src
python scripts/fetch_chips.py   --points points_clean.csv --outdir . --workers 8
python scripts/build_sheets.py  --chips chips --outdir .
```

### 实测结果
- 点位质检：24 点，重复 0、不可解析 0、越界 0；
- 切片：**24/24，用时 39 s**（z18，0.5 m，Esri 直连），源分布全 Esri；
- 联系表：6 张 2×2（512 原生），批次清单只含编号（盲判纪律生效）。

### 判读验证（人工/模型实读 2 张 = 8 点）
- **影像质量足够判结构**：田块边界、收获后的割茬与车轮痕迹、防护林带、盘山土路、格田田埂全部可辨；
- **水稻可判**：NER004 呈"绿格田 + 红褐田埂 + 防护林"的教科书形态 → 高置信水稻；
- **玉米/大豆判不了**：NEM001/004、NER001/003 都是"均匀绿冠层 + 隐约行向"，同一季单期上玉米与大豆同款；
  NEM003 是**收获后**的茬地（瓦片影像无日期，看起来像裸地）。

### 暴露的问题 → 修复
| # | 问题（新用户视角） | 修复 |
|---|---|---|
| R1-1 | **没有"有日期"的影像**：作物细类无法判，且高分底图可能是别的年份/季节 | 新增 `scripts/s2_timeseries.py`（哨兵 2 生长季多时相 + NDVI/NDWI 指标 + 时序图）；SKILL.md 流程改为"作物细类必做 S2" |
| R1-2 | 判读表单没有物候提示，判读时要另开文件对照 | `prep_points.py --metrics` 把 S2 指标写成"指标提示"列，与空白判读列同表 |
| R1-3 | 用户给的是 **Shapefile/XLSX**（GIS 习惯），不是 CSV | `prep_points.py` 支持 `.shp/.gpkg/.geojson/.xlsx`（自动转 WGS84 并抽 lon/lat，已用 24 点 shp 实测通过） |
| R1-4 | 不知道一套流程要多久 | SKILL.md 写明实测速度：高分 ~1.6 s/点、S2 ~1.5–3 min/点（跨境 S3 限制） |

## 轮 2｜"南方多云、底图糊/旧，玉米和水稻怎么分？"

### 新增能力（本轮建设）
1. **`s2_timeseries.py`**：STAC 免密钥取数（earth-search），逐点取生长季 ≤N 期影像
   - 关键实现（都是踩坑换来的）：
     * 用 **WGS84 footprint 几何筛景**，不做"开文件试读"筛选——实测每开一个 COG 要 4–5 s，用它筛选会拖到分钟级；
     * 经纬度**先投影到该景 CRS 再取窗**（直接喂经纬度给 UTM 变换会读出 0×0 空窗，静默失败）；
     * 单点四波段**并行读**（跨境延迟主导，串行 5 期要 8 分钟）；
     * **逐窗云掩膜**：窗口内 88 分位以上同时亮的像元判为云，占比 >50% 弃该期（只有"景级云量"不够——实测 07-17 景云量 20% 但点上正好糊）；
     * `flood_evidence` 用**生长季前 40% 期的 NDWI 最大值**判（用全季最小值是反的：植被期 NDWI 本来就负）；
   - 产出：`s2/<id>_时序.png`（5 期真彩缩略条 + 日期 + NDVI/NDWI 曲线） + `s2_metrics.csv`（增量落盘，可断点续跑）
2. **作物决策树 + 区域农时表**（`references/地类判读图谱.md`）：水稻/玉米/大豆/小麦/棉花/油菜/甘蔗/果园/茶园/大棚/蔬菜/地膜/养殖塘逐项判据（"影像上看到什么"）+ 六大区域农时窗口 + 时序指标阈值 + 混淆速查。

### 判读验证（实读时序材料，三作物对照）
| 点 | 先验 | 5 月 | NDVI 峰值日 | 振幅 | 9 月下旬 | 与高分图互证 |
|---|---|---|---|---|---|---|
| NEM003 | 玉米 | 裸土棕 | **07-31** | 0.71 | 收割回落（棕+绿树） | 高分图见割茬+车辙 → 一致 |
| NER006 | 水稻 | 裸湿 | **07-13** | 0.67 | 整田转黄 | NDWI 前期高、随冠层闭合下降（泡田—封行） |
| NES001 | 大豆 | 裸土 | **08-07** | 0.71 | **9 月中叶片先黄** | 油料作物早衰型黄化 |

**判别链成立**：峰值日期排序明显（稻 7 月中 < 玉米 7 月末 < 大豆 8 月上旬），大豆成熟期先黄、玉米留高茬——
配合高分图行距/管理痕迹，东北"水稻/玉米/大豆"三级可分。该对照表已写回 `references/地类判读图谱.md` 与 SKILL.md。

**结论**：单靠高分只能到"耕地"；**高分结构 + 时序物候 + 管理特征**三合判后才能到作物种级；
玉米与大豆建议"峰值日期 + 成熟期颜色 + 茬高 + 轮作格局"取两项以上再定案。

### 性能与限流（如实记录）
- 单点端到端 **97 s**（首测）；6 点×4 波段并行时单点劣化到 **~290 s**——总连接数 >24 会互相拖慢，**实测甜点 ≈12 连接**（脚本默认 workers=3 × 内层 4 波段）；
- 连续大批量取数后出现 **AWS 侧限流**（单景读窗从 18 s 涨到 60 s+），此时应停手换时段或改走 GEE；
- 因此全量 24 点的 S2 材料本轮只产出 18 点即收手，三作物判别验证改用 **12 点子集 + 已产出成果**完成。
  脚本已支持断点续跑（已存在切片跳过、指标表增量落盘），补跑无重复成本。

### 暴露的问题 → 修复
| # | 问题 | 修复 |
|---|---|---|
| R2-1 | 免密钥 S3 跨境慢（单文件 open 4–5 s，单点 1.5–3 min） | 脚本默认降期数（5 期）并支持 `--res-m 30`；SKILL.md 写明" >30 点建议分批过夜或改走 GEE" |
| R2-2 | 中文标签在时序图上渲染成方框 | 字体回退链加 `msyh.ttc/simhei.ttf`（实测修复，新版图像中文正常） |
| R2-3 | 指标表只在全部跑完才落盘，中断即无 | 改为**每 5 点增量落盘**（断点续跑） |
| R2-4 | `flood_evidence` 判据方向写反 | 改为生长季前期 NDWI 最大值判据，并补存 `ndwi_max/ndwi_first/ndwi_argmax_date` 便于复查 |

## 轮 3｜"这批判读要写进论文/交付给 GIS 同事，怎么证明可信？"

### 实测动作（干跑，用轮 1 的 24 点）
```
python scripts/qc_protocol.py sample --labels form_filled.csv --outdir qc --strata-col src \
        --double-pass 0.15 --audit-per-strata 3     # → 复判 9 点、审计 2 点（盲判清单）
python scripts/merge_stats.py  --base points_clean.csv --labels form_filled.csv --outdir . \
        --prior-col 先验类 --strata-col src --threshold 0.4
python scripts/points_to_shp.py --csv merged_labels.csv --outdir shp --gcj02
```

### 实测结果
- 复判/审计盲判清单正确生成（只含 `point_id`，不含先验列）；
- 统计报告含：总数、无法判读占比、**确认率 0.909（分母口径写明）**、按先验类/按分层分组表、判"否"的实际类 top、敏感性、复判一致率位（两遍输入时自动出）；
- SHP 双版本导出成功，回读校验 24 要素、无超长字段；
- 字段对照表生成（中文列名 → ASCII 短名）。

### 暴露的问题 → 修复
| # | 问题 | 修复 |
|---|---|---|
| R3-1 | 用户不知道"复判/审计批次拿到之后怎么继续" | `qc_protocol.py sample` 的摘要里直接打印下一步三条命令（含盲判→复核→合并），SKILL.md 同步 |
| R3-2 | 判读纪律容易被"先验标签"污染 | `prep_points.py` 在质检摘要里固化"盲判纪律"提示；SKILL.md 把盲判列为硬规则第 1 条 |
| R3-3 | 交付坐标系：国内用户叠加高德/省界会整体偏 300–700 m | `points_to_shp.py --gcj02` 双版本输出 + 字段对照里写明"勿混用"；手册记录偏移实测量级 |
| R3-4 | 报告容易被当成"精度"引用 | `merge_stats.py` 报告末尾固定输出"口径声明"（一致率≠精度；AI 判读须标注复核状态） |

## 三轮总结：从"能不能跑"到"能不能交付"

| 维度 | 轮 1 | 轮 2 | 轮 3 |
|---|---|---|---|
| 目标 | 链路通 | 细类可判 | 结论可信可交付 |
| 新增 | 3 脚本 + 骨架/联系表 | S2 时序 + 作物决策树 | QC 协议 + 统计报告 + 双坐标 SHP |
| 实测证据 | 24 点 39 s 出切片 | 时序曲线与农时一致（2 类复核 8 点） | 24 点全链路过 + shp 回读校验 |
| 关键修复 | 支持 shp/xlsx 输入 | 云掩膜/洪水判据/中文字体/增量落盘 | 复核清单上手引导/口径声明/坐标双版 |

**留给用户的边界**：本 Skill 的判读是"AI 判读 + 可复现证据"，正式论文结论仍需人工复核或双人盲判；S2 免密钥路径适合 ≤30 点的抽检，规模化请走 GEE 批量。
