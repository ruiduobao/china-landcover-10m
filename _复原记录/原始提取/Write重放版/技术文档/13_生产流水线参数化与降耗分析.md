## 1. 配置驱动改造（让全国分类直接复用本次代码）

所有试点脚本（p2-p8）经 `pilot_common.PC` 耦合。本次把区域参数收进唯一配置文件：

```jsonc
// 数据/本地处理/生产配置.json
{
  "area_name": "beijing_r1",
  "bbox": [115.4, 39.4, 117.5, 41.1],        // 全国: [73,18,135,54]
  "years": [2017,2018,2019,2020,2021,2022,2023,2024],
  "anchor_year": 2020,
  "train_file": "数据/本地处理/北京试点/samples_bj_train_r1.parquet",
  "holdout_file": "数据/本地处理/北京试点/samples_bj_holdout_r1.parquet",
  "out_dir": "数据/本地处理/北京试点R1",
  "task_prefix": "CNLC10_BJR1",               // 全国: CNLC10_CN
  "region": "北京市"                           // 全国: "中国"（DataV 全境）
}
```

**全国生产时的全部改动 = 改这一个 JSON**（bbox/region/out_dir/task_prefix/train_file 指向全国 r1_train），p2-p8 代码零修改。

### 各脚本职责与 I/O
| 脚本 | 输入 | 输出 | 改造点 |
|---|---|---|---|
| p2_sample_embeddings | 配置样本文件（r1，含 lon/lat）| {out_dir}/samples_bj_{train,holdout}.parquet（+64维嵌入+lon/lat 直存） | 新增配置分支；properties 携带 lon/lat（消灭旧版 v2 桥接） |
| p3_train | train 嵌入文件 | models_pilot/{rf_bj.joblib, trees_bj.json, p3_report.json} | OUT_DIR 配置化；分层权重扩展（gold1.0/silver0.7/bronze0.5/external0.6/uncovered0.4） |
| p5_submit | trees_bj.json | {out_dir}/tasks.jsonl（8 年 batch 任务） | PLAN 由 YEARS×TASK_PREFIX×账号轮换生成；region=area_geojson() |
| p5b_monitor | tasks.jsonl | 状态轮询、卡死取消重提 | 未改 |
| p6_download / p7_postprocess / p8_validate | assets → GeoTIFF → 一致性 → 精度 | 未改（OUT_DIR 经 PC 跟随配置） |

### 兼容性
无 `生产配置.json` 时全部脚本回退旧默认（北京 v2 路径），旧报告可复现。

## 2. 小区域试验设计（本次执行）

- 区域：**北京全域**（与旧试点同域，构成"新样本 r1 vs 旧 v2 样本"的 A/B 对比，基线 OA 90.11%）
- 训练/留出：r1_train 北京子集按 0.25° 整格 75/25 划分（9,199 / 2,988，防空间泄漏）
- 年份：2017-2024 八年逐年全量分类（p5 提交 8 个 batch 任务，toAsset UInt8 10m）
- 预计 GEE 消耗：~45-50 EECU·h（旧试点实测 45.1）；墙钟 1-2 天（3 账号各 1 并发）

## 3. 资源测算（全国，基于实测）

| 环节 | EECU·h | 时间（10 社区账号） |
|---|---|---|
| r1_train 嵌入提取（299 万点×2020，~258 块交互式） | <100 | 2-4 h |
| e2 清洗 + e3 分区训练 + 树迁移（本地） | 0 | 半天 |
| 全国 2017-2024 逐年 batch 分类 | **12,600-15,500**（实测 band-px 0.8e-9h 推算 ~13,400） | **10-14 天**（10 账号×1 并发） |
| 下载镶嵌+时序一致性（本地，滚动） | 0 | 尾部 +2-3 天 |
| **合计** | **~13,400** | **~12-15 天** |

预算 10 账号×8 仓×150h=12,000h → 降耗措施（§4）落实后 **~7,000-9,500h，可全额覆盖并留余量**。

## 4. 降耗不降精度分析（按代码逐条）

p5 每年任务的成本结构：`年度嵌入集合读取（24 波段）→ mosaic → 逐像元树评估（150 棵×深15）→ uint8 写出`。逐项可省空间：

| # | 措施 | 预计节省 | 精度风险 | 状态 |
|---|---|---|---|---|
| 1 | **region 用陆地多边形而非 bbox**（全国版必须：DataV 全境联合去海） | 15-25%（渤海黄海东海 + 澜沧江外流区外像元） | **零** | 北京已用市界 ✓；全国必做 |
| 2 | **top-24 特征输入树**（p3 内建 top-M 选择） | 20-35%（输入读取与 select 阶段近似线性） | ~0.2pp（北京实测 64 维 vs top-24 留出差）；以留出集 A/B 兜底 | 已内建 ✓ |
| 3 | **树规模 150→100-120 棵、深度 15→16** | 20-30%（树评估近线性） | 通常 ≤0.3pp；北京留出集验证后才采纳 | 待北京试验验证 |
| 4 | 年度任务独立 mosaic、输出 uint8 单波、tileScale 调优 | 已最优 | — | 已做 ✓ |
| 5 | ~~未变化像元继承~~（结构性省 50-70%） | — | **不可靠**：PIF 漂移 0.87-0.98 已证两点检测失效（p1），弃 | 不采纳 |

**组合效果**：#1+#2+#3 → 全国 8 年 **13,400h → 7,000-9,500h**，即 12,000h 预算内完成 8 年全量且留 20%+ 余量；三步全部可用北京 2,988 点留出集做"降耗前后 OA 差 ≤0.3pp"的量化验收。

## 5. 全国生产操作序列（Runbook v2 摘要）

1. 改 `生产配置.json`（bbox=[73,18,135,54]、region=中国、out_dir/task_prefix、train_file=全国 r1_train）
2. `p2`（10 账号并行交互提取，或先 3 账号）→ `p3`（全量分层训练）→ G2 门禁
3. （可选）先提交 1 个 2° 试验瓦批抽检精度 → 再放量
4. `p5` 提交 8 年任务（250-350 个 0.25° 瓦任务、队列深度 ≤3 仓/账号）→ `p5b` 每日巡检
5. `p6` 滚动下载 → `p7` 镶嵌+时序一致性 → `p8` 对 CLCD/WC 与 r1_validation 独立验证

## 6. 监控与断点

- 任务清单 `{out_dir}/tasks.jsonl` 记录 taskId/asset/状态；p5b 按 1 RUNNING+1 PENDING 纪律管理
- 嵌入提取断点：emb_parts/chunk_*.parquet 存在即跳过；bad/ 目录存失败块
- 北京 8 年 batch 预计 1-2 天完成，完成后自动可跑 p6-p8 出精度对比报告
