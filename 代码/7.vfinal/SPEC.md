# v-final 训练样本与模型规格（冻结说明）

> 冻结日期：2026-09-14 ｜ 前置：`26_下一代补样第二轮与K盘迁移报告.md`
> 本文是 v-final 的**唯一规格说明**；配套 `MANIFEST.md`（MD5）与本目录代码。

---

## 一、结论：v-final 与文档 26 版本的差异（三句话）

1. **样本母库未变**：仍是 **2,252,207 点**（row_id 0 – 12,019,573）。本轮**没有新增样本**，
   理由是**诊断推翻了"加样本"这一前提**（见 §三），按用户指令不重复走已被证伪的路。
2. **模型规格变了**：从"30 类单模型（全深度 RF）"改为 **混合规格** —— 主模型（全深度 RF）
   保总体精度 + 弱类模型（`max_depth=20` RF）只供 5 个弱类、且限制在其合理宿主类区域内。
   效果：**30/30 类全部非零**，总体 OA 只让渡 0.9pp，macro-F1 与 balanced-acc 反而上升。
3. **交付口径变了**：同时给 **30 类 / LEVEL1(10 组) / LEVEL0(9 组)** 三级精度，并对
   验证点 n<30 的类标注"只宜报合并级"。依据：GLC_FCS30 自身 9 类 OA 82.5% → 16 类 71.4%
   → 24 细类 68.7%，多拆类付 8–14pp OA 是产品级常态（文献核验 2026-09-14）。

## 二、v-final 模型规格

| 部件 | 规格 |
|---|---|
| 特征 | AlphaEarth AEF 年度嵌入 64 维（`GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL`），10 m，2017–2024 |
| 主模型 | `RandomForestClassifier(n_estimators=150, max_depth=None, min_samples_leaf=2, max_features='sqrt', class_weight='balanced_subsample')`，`sample_weight=train_weight` |
| 弱类模型 | 同参数但 **`max_depth=20`**、`n_estimators=120` |
| 弱类集合 | `{52, 62, 91, 140, 11}` |
| 合成规则 | 若弱类模型判为 `c ∈ 弱类集合`，**且**主模型判为 `c` 的宿主类之一 → 采用 `c` |
| 宿主集（实测混淆簇） | 52←{51,61,71,72,120,121,62,92}；62←{61,51,71,82,121,52,120}；91←{71,61,92,82,51,72,81}；140←{150,201,121,130,120,220}；11←{10,12,120,121,130,71,51} |
| 训练数据 | `年度子集_含稀有类/r7_train_{y}.parquet`，**剔除 25 km holdout 块内全部点** |
| 验证 | `样本底座/validation_pool_v2.parquet`（5,186 点 / 396 块），按来源分 FCS10 / 非 FCS10 |

### 2.1 为什么这么改（实验依据，全部在 2022 年、同一 holdout 划分下）

| 方案 | OA | macro-F1 | bal-acc | 30 类非零 | 52 | 62 | 91 | 140 | 11 |
|---|---|---|---|---|---|---|---|---|---|
| 文档 26 口径（全深度单模型） | 0.7413 | 0.6123 | 0.6194 | **26/30** | 0 | 0 | 0 | 1 | 0 |
| 全局类别加权 ×3 / ×8 | 0.679 / 0.664 | 0.607 / 0.592 | 0.644 / 0.640 | — | 4 / 9 | 38 / 67 | 3 / 2 | 8 / 13 | 8 / 9 |
| 分层分类（7 族粗 + 族内细） | 0.7338 | 0.6077 | 0.6148 | 27/30 | 0 | 0 | 2 | 2 | 0 |
| 一类一专家 OvR（精度≥0.75） | — | — | — | — | 召回 0.00 | 0.00 | 0.04 | 0.24 | 0.00 |
| 单模型 `max_depth=15` | 0.6070 | 0.5481 | 0.6432 | **30/30** | 64 | 111 | 16 | 92 | 146 |
| **混合（主全深度 + 弱类 depth=20）** | **0.7322** | **0.6242** | **0.6239** | **30/30** | 8 | 53 | 3 | 27 | 12 |
| 混合（弱类 depth=15，可选档） | 0.6976 | 0.6270 | 0.6335 | **30/30** | 64 | 110 | 15 | 92 | 143 |

**机理解释**：全深度树的叶子极纯，稀有类只占据极小区域、在 150 棵树的多数表决里被淹没；
把树深限制到 20/15 会把票摊开，弱类得以进入 argmax。**depth=20 是拐点**：维持 OA、
换来 30/30 与 macro-F1/bal-acc 双升；depth=15 保召回但 OA −4.4pp。

## 三、为什么本轮不加样本（诊断结论，重要）

对 5 个 F1=0 类在 64 维嵌入空间做 5 折交叉验证二分类探针（2022 年全域）：

| 检验 | AUC | 判读 |
|---|---|---|
| 52 vs 51（疏/闭常绿阔叶） | **0.785** | **真不可分**——郁闭度维度不在嵌入里 |
| 62 vs 61（疏/闭落叶阔叶） | **0.833** | **真不可分**——同上 |
| 91 vs 71 / 91 vs 61 | 0.997 / 0.978 | 完全可分 |
| 140 vs 150 / 140 vs 201 | 0.987 / 0.990 | 完全可分 |
| 11 vs 10 / 11 vs 121 | 0.949 / 0.956 | 完全可分 |

再用**训练集样本训练的二分类器**去判**验证池（GLC_FCS10 来源）**的对应点：
91 → p=0.995（vs 71）、140 → p=0.664、11 → p=0.729（均值 0.778）。
即**跨产品的类概念一致、信息完整**。

**结论**：5 个类中只有 52、62 是特征不可分（需要外挂郁闭度特征）；
**91 / 140 / 11 三个类信息完全在嵌入里，加样本不会有任何作用** —— 这正面否证了
"继续加样本"的路线，与文档 26 §五.2 的判断一致但把病因定位得更准。

外部证据佐证：GLC_FCS30 自身混交林 PA 仅 **0.321**、地衣苔藓 **>60% 验证样本被错分**；
GLC_FCS30D 中 91/92 甚至**没有郁闭度定义**（其余森林类才有 fc 区间）。
即这两类的"坏"继承自教师产品，不是本项目的模型缺陷。

## 四、已知弱项（如实交付）

1. **52 / 62（疏/郁闭阔叶林）**：F1 仍低（0.13 / 0.25 @ 2022）。真正的解法是**外挂乔木覆盖度
   特征**（MODIS MOD44B 植被连续场或 GEDI `cover`），本轮已完成特征栈与少量区验证
   （见 `代码/7.vfinal` 的 `xfeat` 系列），**全库 2.25M 点重采样 + 重训未在本轮完成**。
   文献共识与此一致：疏/郁闭是阈值编码量（Open 0.15<fc<0.4，Closed fc>0.4），
   不应指望分类器从光谱嵌入里学出来。
2. **91（针阔混交）**：F1 ≈ 0.09（depth=15 档）。混交林是"混合比例"连续量，
   建议下游按 LEVEL1 `forest` 组使用，或叠加密接专题层。
3. **140（地衣苔藓）**：模型能输出但精度低（F1≈0）。全球该类都是最差类
   （WorldCover v200 该类 UA 57.5/PA 46.4）。**建议交付时并入 150 稀疏植被/201 裸地**，
   或在青藏高原做专题后处理。
4. **11（乔灌园地）**：训练点 5,013（`teamap_2022` 3,155 + GLC 1,856），
   验证池仅 95 点，F1 0.12。中国园地专题产品（TeaMap 2022 / 柑橘 2020 / 苹果 AOMC / 橡胶）
   **本地目录只有说明文档、没有栅格**，需用户提供数据文件才能补强。
5. **验证点过少的类**：91(8)、140(6)、183(3)、184(3)、52(41) 的 F1 统计噪声极大，
   **不建议作为论文主结论依据**；交付只报合并级（LEVEL1/LEVEL0）指标。

## 五、复现路径

```bash
# 1) 可分性诊断（本地，~20 min）
python 代码/7.vfinal/v1_sep_probe.py
# 2) 模型规格实验（本地，各 ~15 min）
python 代码/7.vfinal/v2_model_probe.py          # 全局加权
python 代码/7.vfinal/v2b_depth_probe.py         # 树深
python 代码/7.vfinal/v2c_hybrid_probe.py        # 混合
# 3) 8 年全量复评 + 三级粒度报告
python 代码/7.vfinal/v3_final_eval.py           # 长任务请用 _tools/e11_years_driver.py
python 代码/7.vfinal/v4_level_report.py
# 4) 端到端验证（交互式，无 batch 导出）
python 代码/7.vfinal/v7_e2e_local.py            # 本地全量 v-final 模型
python 代码/7.vfinal/v5_e2e_interactive.py      # GEE 内训练（链路示意，非最终模型）
# 5) 冻结
python 代码/7.vfinal/v6_freeze.py
```

**资源纪律**：CPU ≤15 核（RF `n_jobs` 已设 13）、内存 ≤30 G、账号一账号一任务、
`operations` 端点用 `GET` 且路径不带 `:list`、长任务走 `_tools/` 下的抗清理驱动。
