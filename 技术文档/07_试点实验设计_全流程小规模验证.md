# 试点实验设计：全流程最小规模验证（Pilot）

> 目的：**用尽可能少的资源，把 02–06 文档的全部代码与流程端到端真实跑一遍**，并产出三样东西——①逐阶段的产出物与门禁结果；②"降本不降质"的实测证据（PCA K、特征选择 top-M、级联、量化是否损精度的定量对比）；③生产启动所需的实测参数（每项目并发数、阈值、单任务耗时）。
> 定位：本试点 = "1°瓦片配额压测"（02/05 文档承诺）+ 全流水线集成测试 + 优化措施验证，三合一。

---

## 1. 试点目标与验收标准

**一句话目标**：在 1 个 1°×1° 瓦片、3 个年份、2 个账号的资源下，把"样本生成 → 提纯 → 训练 → 模型迁移 → GEE 分类 → 变化检测 → 只重分类变化区 → 后处理 → 镶嵌 → 验证 → 调度器"全部代码跑通，并给出关键参数的实测值。

**总验收门（全部通过才算试点成功）**：

| 门 | 指标 | 依据 |
|---|---|---|
| G1 数据可用 | AEF 嵌入年份/波段核查通过（02 §2.3 脚本） | 02 |
| G2 样本管线 | 提纯前→后样本量、类分布符合预期；无 0 样本类 | 03 |
| G3 模型一致性 | sklearn 与 GEE 端预测不一致率 = 0（<0.1% 边界容忍） | 06 §7 |
| G4 分类质量 | 试点瓦片 Level-1 验证 OA ≥ 85%（200 点目视验证集） | 02 §1 |
| G5 变化检测 | 2019/2021 变化像元占比 0.5%–15%（合理区间），伪变化目视抽检 <1% | 04 |
| G6 降本证据 | 64 维 vs top-M、全波段 vs PCA-K 的精度差 <1pp；量化前后变化掩膜一致 >99.9% | 05 §7 |
| G7 调度器 | 2 账号×2 项目并发、失败重试、断点恢复演示通过 | 02 §8 |
| G8 资源账本 | 实测任务数/耗时/Drive 量 ≤ 预算表（§4），据此反推全生产资源 | 05 |

## 2. 试点范围

### 2.1 空间范围：1 个瓦片 E115–E116°E, N40–N41°N（北京西北）

**选择理由**（一个瓦片内覆盖最大景观梯度）：

| 地物 | 位置 | 覆盖类别（本产品码） |
|---|---|---|
| 军都山/八达岭山地 | 西北部 | 落叶阔叶林(61/62)、常绿针叶林(71/72)、针阔混交(91/92)、灌丛(120/121)、草地(130) |
| 延庆盆地农田 | 中部 | 旱地(10)、灌溉耕地(12，含部分水浇地) |
| 官厅水库及库滨 | 西南部 | 水体(202)、湖滩地(182) |
| 城镇与村庄 | 延庆城区/乡镇 | 城镇(190)、乡村不透水(200) |
| 采石场/裸岩 | 山前局部 | 裸地(201) |

预计可覆盖 **12–14 个精细类**，含典型易混对（草地-灌木、水-滩地、农田-草地）。**有意不含**稀有类（红树林等）——试点目标是"跑通代码"，不是"覆盖全部 30 类"；稀有类平衡逻辑用"人为欠采样模拟"验证（见 S2）。

### 2.2 时间范围：2019、2020、2021 三年

- **2020 = 锚年**：全图 RF 分类（重锚路径）；
- **2019 / 2021 = 前向/后向传播**：嵌入变化检测 → 只重分类变化像元（04 文档主路线）；
- 3 年堆栈同时驱动后处理 HMM/平滑路径（02 §7.2）。

### 2.3 刻意包含的"变体测试"（不增加成本）

| 变体 | 做法 | 验证什么 |
|---|---|---|
| 特征选择 | 同一样本训练 top-16 与 64 维两个 RF | 05 §4.3 的"不损精度"断言 |
| 降维变化检测 | 变化检测在 PCA-K 上做，K 本地定为 ≥95% 方差 | 05 §4.1 的召回/误报对比 |
| Int16 量化 | 精简嵌入栈物化时同时物化 float32 与 Int16 两版 | 05 §4.4 的掩膜一致性 |
| 分半镶嵌 | 同一瓦片切两半分别导出再镶嵌 | 02 §8.4 的接缝/对齐 |
| 稀有类模拟 | 提纯时人为把草地类欠采样成"稀有类" | 03 §5 平衡代码路径 |

## 4. 阶段分解（S0–S8）

> 每阶段标注：做什么 → 用哪份文档的哪段 → 产出物 → 门禁。

### S0 环境核查与准备（0 成本，1 小时）

- 跑 02 §2.3 嵌入核查脚本（年份/波段/分辨率）；**门禁 G1**；
- 建 4 个 Project 的凭据池与 `tasks.jsonl` 骨架（05 §8.3 调度器）；
- 建中央资产目录（原型/精简栈 Asset 归属），发布统一 `cfg.json`（特征顺序单一事实来源，06 §3）。

### S1 样本生成（GEE 2–3 个小表任务）

- 在试点瓦片内跑 02 §6.3/03 §6 的采样脚本（改造自已有 `2.0数据生成代码.js`）：GLC_FCS30D 2020 年 ±3 年稳定 + CCDC `tBreak/nBreaks` 筛选 + 1° 格内分层采样 **3000–5000 点**；
- 产出：`samples_pilot_2020.csv`（含 lon/lat/class/year/tile_id/conf）；
- 门禁 G2：各类样本数 ≥ 30，无 0 样本类。

### S2 样本提纯（全本地，30 分钟）

- 按 03 文档四阶段跑：多产品投票（ESRI/CLCD 就近年）、马氏距离+卡方清洗、原型过滤、√面积+稀有保底平衡；**刻意欠采样草地模拟稀有类**（03 §5.2 路径）；
- 产出：`samples_pilot_clean.parquet` + 提纯日志（前后数量/类分布对比表）；
- 门禁 G2 续：提纯后各类仍有 ≥20 点；稀有类模拟路径正常。

### S3 训练与模型迁移（全本地 + 1 次 GEE 校验）

- 本地 sklearn：64 维 RF 与 top-16 RF 各一（06 §2）；转换 `ee.Tree`（06 §5）；
- **一致性校验**（06 §7）：5000 点本地 vs GEE 预测，不一致率应为 0；
- 产出：`rf_pilot_full.joblib` / `rf_pilot_top16.joblib` / 各自 `_gee_trees.json` + 校验报告；
- 门禁 **G3**（必须零不一致才能进 S5）。

### S4 精简嵌入栈物化（GEE 4–6 个 Asset 任务）

- 本地算 PCA 载荷 W（样本上，K 取 ≥95% 方差）与 top-M 波段清单（本地验证不损精度）→ 上传 W（几十 KB）；
- GEE 内对 3 年嵌入做"投影 + 特征选择 + Int16 量化"，物化精简栈 Asset：`emb_pilot_{2019,2020,2021}_k{12}_q`（float32 版 1 年、Int16 版 3 年，供量化对比）；
- 产出：精简栈 Asset 3–4 个 + W 载荷本地存档；
- 门禁：物化成功、波段数正确；**为 G5/G6 提供输入**。

### S5 锚年分类 + 变化检测 + 只重分类（GEE 主要计算，6–10 个任务）

1. **锚年**：2020 精简栈(64 维 float32 版) → `decisionTreeEnsemble` 全图分类 → 导出 UInt8；
2. **变化检测**：2019/2021 嵌入(Int16 降维版) vs 2020 → 超球面参考+角距离+CUSUM（04 §4）→ 导出两年变化掩膜；
3. **只重分类**：变化像元用"变化后段均值嵌入"再分类（04 §4.4），未变化继承 → 导出 2019/2021 分类图；
4. **变体**：同一年分类同时用 top-16 RF 跑一遍（对照精度，G6）；
- 门禁 **G5**（变化占比区间 + 伪变化目视抽检）。

### S6 后处理与镶嵌（全本地）

- 3 年类别堆栈 → HMM/平滑（02 §7.2，本地 numpy）；QC 层生成；
- 分半镶嵌：瓦片两半 → GDAL 镶嵌 → 接缝/像元对齐检查（G6 顺带）；
- 产出：`CNLC10_{2019,2020,2021}_pilot.tif`（后处理版）+ QC 层 + 镶嵌检查报告。

### S7 验证（全本地 + 小量影像导出）

- 构建 **200 点目视验证集**（分层随机，Google Earth Pro/天地图解译，兼职可参与）；
- 混淆矩阵（Level-1 与 Level-2 两档），OA/κ/UA/PA；
- 与 GLC_FCS10(2023 邻近)、CLCD 在瓦片内做切片对比（02 §9）；
- 产出：验证报告 + 对比切片图（Drive 导出 2–3 张小图）；
- 门禁 **G4**（Level-1 OA ≥85%）。

### S8 调度器与多账号演练（贯穿 S4–S5 全程）

- 所有任务经调度器提交（05 §8.3）：2 账号×2 项目轮换、并发上限（试 3→6→10 实测）、模拟 2 个失败任务验证重试与断点恢复；
- 记录：每任务耗时、错误类型、并发上限实测值；
- 门禁 **G7** + **G8 前半**（资源账本）。

### S9 试点总结（本地，1 天）

- 汇总 G1–G8 结果表 + 资源账本；
- **决策输出**：
  ① 生产可行性与预期全资源（用实测单任务耗时 × 全任务数反推 200 项目排期）；
  ② 定稿参数：PCA K、top-M、变化检测 τ/κ/h、每项目并发、tileScale/shardSize；
  ③ 是否需第二轮试点（如换一个南方多云雾瓦片验证嵌入鲁棒性）。

## 6. 试点不覆盖项（明确豁免，避免误解）

| 豁免项 | 原因 | 生产时的保障 |
|---|---|---|
| 全部 30 类（红树林等稀有类） | 试点瓦片不含；目标为代码路径覆盖 | 03 §6 稀有类定向采样逻辑已在 S2 以"模拟稀有类"验证 |
| 9 年全部年份 | 3 年覆盖"锚年+前向+后向"全部代码路径 | 2025 外推特殊逻辑需另测（列为第二轮试点候选） |
| 全中国/全瓦片 | 试点 1 瓦片 | G8 实测参数 → 全生产排期 |
| 大规模多账号并发（20×10） | 试点 2 账号×2 项目即可验证机制 | 调度器按项目数参数化，扩容无需改代码 |
| 2025 年外推机制（DW 补全） | 成本高 | 第二轮试点单独设计 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 试点瓦片类别不够多样 | 训练路径覆盖不全 | 选瓦片前先用已有 2020 样本统计该瓦片类别数（本地即可，0 成本）；不够则换 E114–115/N39–40 |
| GEE 单任务报错（内存/超时） | 试点卡壳 | 本身就是压测目的：记录错误→调 tileScale/shardSize/并发，重试 |
| 一致性校验不过 | 转换代码有 bug | 先本地排查（特征顺序/阈值精度），再重转换；门禁 G3 严格把关 |
| 验证 OA 不达标 | 可能反映样本或参数问题 | 先查样本纯度（03 §7 抽检）与类别混淆矩阵，定位后回到 S2/S3 迭代 |
| 试点任务挤爆单账号日配额 | 拖长时间 | 2 账号轮换 + 错峰（05/02 §8 调度规则） |
