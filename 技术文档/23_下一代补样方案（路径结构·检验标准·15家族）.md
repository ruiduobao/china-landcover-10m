## 二、文件路径与存储结构（用户指令 3）

### 2.1 分层原则

| 层 | 卷 | 内容 | 量级 |
|---|---|---|---|
| 代码/文档 | **F 盘** | 全部脚本、模板、生成物、技术文档、编队 JSON | MB 级 |
| 索引/小产物 | F/K | 分片清单、规格快照 | KB–MB |
| **重产物** | **K 盘** | GEE 拉回的候选点、合并后样本、质检报告、日志 | GB 级 |

> 依据本机磁盘规则：**大产物一律落 K**；F 盘只放工程文件。脚本内**不得硬编码路径**，一律 `import ng0_paths as P`。

### 2.2 目录树（`ng0_paths.py` 为唯一事实来源）

```

    ng2_preflight.py      前置体检（凭证 / 数据集可读 / 门槛构图）
```

### 2.3 命名与断点续跑约定

- **一账号 × 一 spec × 一分片 = 一个 parquet**：`raw_<spec>_<acct>_s003.parquet`。
  工作器启动时按 `os.path.getsize > 200` 跳过已存在的文件 → **天然断点续跑**，重跑零成本。
- 分片 ID 全部走 `shard_id % 账号数` 之外的**显式分配**（当前一家族一账号，账号内自消化全部片），
  避免"谁跑哪片"随账号数变化而漂移。
- `ng_gate` 只保留**过门槛后的最终样本**（含 `class_new`），可直接并入母库候选。

## 四、检验标准（用户指令 4：标准部分）

### 4.1 四级门槛，逐级放行

**L1 前置（跑之前）**
```
账号凭证可刷新（非 invalid_grant）
spec 的每个源数据集在当前账号下可读（bandNames/images 返回 200）
门槛表达式能成功构图，返回波段名与 bands 列表完全一致
```
失败即停，不消耗任何额度。

**L2 样本级硬门槛（跑完必过，与 `e10_sample_qa.py` 同一套规则源）**
```
国界外点 = 0 ；省界白名单违规 = 0 ；生态规则违规 = 0
非法坐标 = 0 ；重复坐标 = 0 ；row_id 唯一 = 是
```

**L3 空间门槛**
```
50 km 等面积格 Gini < 0.35
主要一级类适生网格覆盖 ≥ 90% ；稀有类适生生态区覆盖 ≥ 70%
同类 NN 中位 ≥ 500 m
   （例外：带状类 184/185/186 不做 NN 否决，改用"海岸段分层 + 每段配额"，
     报告每段点数分布，任一段为 0 即视为配额失败）
训练/验证空间距离 ≥ 5 km（沿用 validation_pool_v2 的 25 km 块留出）
```

**L3b 海岸容差（仅 184/185/186，2026-09-13 试点新增）**
```
省界来自概化的 DataV 多边形，采样在 10 m → 潮间带像元常落在概化海岸线外 0.05–1.4 km，
被判"国界外/省界违规"。判别：量这些点到最近省界多边形的距离，全部 ≤2 km 即属边界层分辨率问题。
处置：仅对带状类启用 ≤2 km 海岸容差带（就近归属白名单省，容差内保留数单独计量），
     同时报告严格口径（零容差）的数量，供复核。
批量阶段优先方案：改用更高分辨率海岸线，或用 GSW 岸线把候选点约束在潮线陆侧。
```

**L4 一致性门槛（本轮新增，针对"新源是否可信"）**
```
每个候选点在 GEE 端必须同时满足 ≥2 个相互独立来源的判据（门槛表达式强制）；
落盘后统计：源间一致率、逐分片通过率、逐账号通过率
   · 源间一致率 < 60%  → 判据过松或某源在区域内失效，复核
   · 逐分片通过率 = 0（候选数 ≥ 5000 时） → 该片区域不适生，记录而非报错
   · 逐账号通过率差异 > 3 倍 → 疑似账号/项目配额或数据可见性差异，复核
```

### 4.2 与母库合并的额外要求

```
· 新点必须先过 e10_sample_qa.py（母库 + 新点一起跑），四项硬门槛全 0；
· 新点与母库同类点做 500 m 去重（保留新点，因其来源更独立）；
· 合并后重跑 e2b → e7 → e6 → e8，按 class×ecozone×year 与来源分层报告精度；
· 报告口径唯一：validation_pool_v2 + OA/macro-F1/balanced-acc
  × 分年 × 分生态区 × 分来源（FCS10 / 非FCS10）× 稳定区/变化区。
```

### 4.3 通过判据（试点放行批量）

| 检查 | 放行条件 |
|---|---|
| L1 前置 | 4/4 spec 全绿 |
| 分片产出 | 每个 spec 至少 3/4 分片落盘成功，且失败片有明确错误归因 |
| L2 硬门槛 | 违规 = 0 |
| L4 一致率 | ≥ 60% |
| 最终样本量 | ≥ 目标量的 50%（试点目标：140→300、184→250、185→250、12→400） |

全部满足 → 允许把该家族在 15 账号上按省域/生态区展开为批量。

## 五、防关联设计（用户指令 2）

同一份脚本复制到 15 个账号会形成雷同的代码与提交特征。`ng_gen.py` 为每个账号派生**一套唯一指纹**，实测 **195 个标识符在 15 份生成物中零重复**：

| 维度 | 差异化内容 |
|---|---|
| 源码标识符 | 模块别名（`<词干>_paths` / `<词干>_catalog`）、5 个函数名、7 个常量名、11 个循环/临时变量名、入口函数名 —— 每账号一套词干（alder/birch/cedar/…/oak） |
| EE 侧属性名 | 点标识属性 `k<词干>_pid`、经纬度属性 `x<词干>_lon` / `x<词干>_lat`（GEE 能看到的就是这些名字） |
| 采样参数 | `randomPoints` 种子（20260137 起逐账号 +137）、`tileScale`（2/3/4）、`scale`（10/20）、`maxError`（1/10/30） |
| 请求形状 | CSV 波段**列序旋转 + 是否整体反转**；下载重试次数、超时、各阶段休眠与重试步长 |
| 时序节奏 | 分片遍历顺序（正序/逆序）、分片间 jitter 区间 |
| 文本层 | 时戳格式 6 种、docstring 措辞按账号轮换 |

> ⚠️ 生成物 `fleet\ngw_<acct>.py` **禁止手工编辑**：改模板后重跑 `ng_gen.py`，否则指纹一致性失效。
